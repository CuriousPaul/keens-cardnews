# 콘텐츠 기획·카피 엔진 — 프롬프트 명세

> 합성 소비자 리서치(Nemotron) → 주제 발굴 → 카드별 카피 → `content.json` 산출
> 한·영 병행 / 톤: '전문가의 정직하고 냉정한 피드백'
> 모든 단계는 주 1회 배치로 다음 주 콘텐츠 풀을 미리 채웁니다.

이 엔진은 3단계 체인으로 동작합니다. 각 단계의 출력이 다음 단계의 입력이 되며, 최종 산출물은 렌더러가 바로 받는 `content.json`입니다.

---

## 0. 공통 컨텍스트 (모든 프롬프트에 주입)

```
[BRAND]
- 회사: C3 — 엔터테인먼트/아이돌 입시·트레이닝
- 핵심 상품: 레벨 테스트(무료 진입) → 유료 프로그램(예: 6개월 $2,400 패키지)
- 타겟 시장: 한국 + 미국 (콘텐츠는 한·영 2벌)
- 페르소나: ① 아이돌 지망생 본인(10~20대) ② 지망생 학부모 ③ K-pop 입시·유학 관심층
- 브랜드 보이스: 솔직하다, 냉정하다, 근거를 댄다, 과장/허세 금지. '현직 전문가의 진단' 톤.
[GUARDRAIL]
- 연습생 멘탈/외모/체중 등 민감 주제는 단정·압박 금지, 건강한 프레임 유지.
- 보장성 표현("무조건 합격") 금지. 데이터·경험 기반으로만 주장.
```

## 1단계 — 합성 소비자 리서치 (Nemotron)

**목적:** 타겟의 *무의식적 불만·죄책감·결정 장벽*을 데이터로 도출.

**프롬프트 틀:**
```
당신은 정성 리서치 분석가입니다. 아래 페르소나를 시뮬레이션해 심층 인터뷰를 진행하세요.
PERSONA: {persona}
주제: 아이돌 입시/트레이닝 과정에서 느끼는 불안과 불만.

다음을 각각 5개씩, 페르소나의 1인칭 진술로 도출하세요:
1) 겉으로 말하는 불만 (stated)
2) 입 밖에 내지 않는 진짜 두려움 (unspoken fear)
3) 결정을 미루게 만드는 장벽 (decision barrier)
4) 죄책감을 느끼는 지점 (guilt trigger)
출력: JSON 배열. 각 항목 {type, quote, insight}.
```

**출력 예 → 인사이트 풀(insight pool)로 누적 저장.**

---

## 2단계 — 주제·앵글 발굴

**목적:** 인사이트 풀 + 트렌드 신호 → 주간 주제 목록(후크 포함).

**프롬프트 틀:**
```
아래 인사이트 풀과 브랜드 컨텍스트를 바탕으로, 인스타 캐러셀 카드뉴스 주제 {N}개를 제안하세요.
INSIGHT_POOL: {1단계 결과}
규칙:
- 각 주제는 '냉정한 전문가 피드백' 앵글일 것.
- 표지 후크는 스크롤을 멈추게 하는 도발적/반직관적 문장.
- 마지막 카드는 항상 레벨 테스트 CTA로 수렴 가능해야 함.
출력: JSON 배열. 각 {topic, angle, target_persona, hook, why_it_works}.
```

선정 기준(스코어링): 후크 강도 · 페르소나 적합도 · CTA 연결성 · 차별성. 상위 항목을 주간 캘린더에 배치.

---

## 3단계 — 카드별 카피 생성 (한·영 2벌)

**목적:** 선정 주제 1개 → 렌더러용 `content.json` 1쌍(ko/en).

**카드 구조(캐러셀 5~8장 권장):**
| 순서 | type | 역할 |
|---|---|---|
| 1 | `cover` | 후크. kicker(소제목) + headline. `<span class='hl'>` 로 강조어 표시 |
| 2~N-1 | `problem` / `insight` | 문제 제기·근거. badge/stat/title/body |
| N | `cta` | 레벨 테스트 전환. headline + button + footnote(DM 키워드 안내) |

**프롬프트 틀:**
```
아래 주제로 인스타 캐러셀 카드뉴스 카피를 작성하세요.
TOPIC: {topic} / ANGLE: {angle} / PERSONA: {persona}
요구사항:
- 카드 5~7장. 구조: cover → (problem/insight) ×3~5 → cta.
- 표지 headline에는 핵심 강조어를 <span class='hl'>...</span> 로 감쌀 것.
- body의 핵심 단어는 <strong>...</strong> 로 강조.
- 줄바꿈은 \n 사용(카드 폭 고려, 한 줄 12~16자 내).
- cta 카드: button 텍스트 + footnote에 DM 키워드 안내.
- 한국어판과 영어판을 각각 생성(영어는 번역이 아닌 현지화).
- dm_keyword: 한글판 '레벨테스트', 영문판 'LEVELTEST'.
- caption: 본문 2~3문장 + 댓글/DM 유도 + 해시태그 10개 내외.
출력: content.json 스키마(ko 1개, en 1개) JSON 두 개.
```

**출력 스키마 = `content.json`** (렌더러 입력):
```json
{
  "post_id": "YYYY'W'WW-{lang}-NN",
  "lang": "ko|en",
  "topic": "...", "angle": "...", "persona": "...",
  "dm_keyword": "레벨테스트|LEVELTEST",
  "cards": [
    {"type":"cover","kicker":"...","headline":"... <span class='hl'>...</span>"},
    {"type":"problem","badge":"착각 1","title":"...","body":"... <strong>...</strong>"},
    {"type":"insight","kicker":"...","stat":"73%","title":"...","body":"..."},
    {"type":"cta","headline":"...","button":"...","footnote":"..."}
  ],
  "caption": "...#해시태그",
  "status": "draft"
}
```

샘플 산출물: `content_sample_ko.json`, `content_sample_en.json` 참고.

## 4. 품질 가드 (자동 검수 후 승인 큐로)

생성 직후 자동 체크:
- 카드별 글자 수 한도(표지 headline ≤ 28자/줄 ≤ 16자, body ≤ 120자) 초과 여부
- 보장성·민감 표현 필터 통과 여부
- DM 키워드·CTA 카드 존재 여부
- 한·영 쌍 모두 생성되었는지

통과분만 승인 큐(Slack/Notion)로 보내고, 반려 사유는 인사이트/프롬프트 개선에 피드백합니다(2장 아키텍처의 Phase 1 루프).

## 5. 운영 캘린더(권장)

주간 배치 1회 → 주제 N개 확정 → 한·영 2벌 = 2N개 게시물 초안 → 승인 게이트 → 스케줄 발행.
초기엔 주 3~4회(한·영 분리 계정/슬롯) → 품질 안정 후 빈도 증대(제안서 '발행량 200%↑' 선행지표).

## 6. v2 업그레이드 (레퍼런스 흡수 — open-carrusel + @prompt_what)

레퍼런스 라이브러리에서 검증된 패턴을 콘텐츠 엔진에 반영한다.

### 6-1. 렌더 지침 3원칙 (모든 카피 생성에 주입)
@prompt_what의 노출된 프로젝트 지침에서 차용. 카피·레이아웃 생성 시 이 원칙을 따른다:
1. **내부에서 정교한 레이아웃을 구성한 뒤 1080×1350 결과만 산출** — 코드/과정은 결과물에 노출하지 않는다.
2. **한 게시물의 가시 텍스트는 한 언어로 고정** (KO판은 한국어만, EN판은 영어만). 혼용 금지.
3. **폰트 안전** — 한글은 Noto Sans KR / Pretendard 계열로 깨짐 방지(템플릿이 보장).

### 6-2. 카드 타입 확장
기존(cover/problem/insight/cta)에 두 타입 추가(검증된 한국어 스켈레톤 "도입→문제정의→관점전환→체크리스트→CTA"):
- `perspective_shift` — 통념을 뒤집는 관점 전환 카드(반전 톤 권장).
- `checklist` — 실행 체크리스트(2~4항목, 체크박스 그래픽).
권장 스켈레톤 옵션: **도입(cover) → 문제정의(problem) → 관점전환(perspective_shift) → 체크리스트(checklist) → CTA**.

### 6-3. CTA = 리드마그넷 공식 (표준화)
마지막 카드 + 캡션의 CTA는 **가치 제안 + 댓글 키워드** 형태로 통일한다(댓글→DM 퍼널 극대화):
> "[무료 자료/진단]을 받으려면 댓글에 '[dm_keyword]'를 남겨주세요."
예) "내 무대 진단 체크리스트를 받으려면 댓글에 '레벨테스트'." (가치+키워드를 한 문장에)
근거: @prompt_what 게시물은 이 방식으로 좋아요(3.2천)보다 댓글(5.9천)이 더 많았다.

### 6-4. 후크 공식 라이브러리(표지)
- **냉정한 진실형:** "심사위원은 [통념]부터 안 봅니다."
- **No-X 배지형:** "[코딩 X / 재능 X] · [성과] [저노력·시간]". (단, Keens 가드레일 내 — 보장성 표현 금지)
- **두려움 명명형:** "'[흔한 불안]' — 그 생각이 진짜 문제입니다."

### 6-5. 비주얼 테마 선택 (브랜드 토큰 외부화)
배치/계정 설정으로 `theme`을 고른다(assets/brand.json):
- `stage-photo`(기본): 다크 시네마틱 스테이지 사진 + 레드 액센트.
- `editorial-gold`(프리미엄): 차콜 #0E1116 + 골드 #C8A24B + 크림 #F3EFE6, 큰 인덱스 숫자·공식/구조 카드. 사진 없이도 고급감(@prompt_what 스타일 차용 — 단 오리지널 카피·레이아웃으로 재생성).
- 특수 카드는 `body_html` 필드로 자유 HTML(open-carrusel `wrapSlideHtml` 패턴) — 공식 카드·바·체크박스 등 표현력 필요할 때.

## 7. v2.1 업그레이드 (Notion "카드뉴스 공장" 프레임워크 흡수 — Keens 재작성)

@prompt_what의 노출된 시스템 프롬프트 구조를 Keens 보이스로 재작성해 흡수한다(원문 복붙 아님, 구조·규칙만 차용).

### 7-1. 10-beat 카드 구조 (장형 캐러셀 기본값)
정보·교육형 주제(오디션/보컬/댄스/입시)는 5장 대신 **10장 골격**을 기본으로 한다:
1. **강한 도입(cover)** — 1문장 훅. 통념 반박/냉정한 진실. 일반적 동기부여 금지.
2. **궁금증 확장** — open loop. "왜 지금 이게 문제인가."
3. **문제 정의(problem)** — 흔한 오해/페인 포인트. 공감되지만 유치하지 않게.
4. **관점 전환①(perspective_shift)** — 당연한 가정을 깬다. 첫 인사이트.
5. **관점 전환②** — 논리 전개. 구체 예시·대비·비유(또는 stat 카드).
6. **핵심 설명(insight)** — 가장 저장가치 높은 메인 밸류.
7. **적용 방식** — 실제로 어떻게 쓰는가(실전·명확).
8. **결정적 깨달음** — 가장 강한 관점 전환.
9. **실행 체크리스트(checklist)** — 짧은 액션 2~4개(체크박스 그래픽).
10. **마무리 CTA(cta)** — 자연스러운 리드마그넷(가치+댓글 키워드, §6-3).
- 짧은 포맷이 필요하면 3·6·9·10장만 살린 5장 압축본 사용 가능.
- 텍스트 밀도: 1장 헤드라인(±서브) / 2–8장 헤드라인+1~3줄 / 9장 체크리스트 / 10장 CTA. **한 슬라이드 한 아이디어, 텍스트 벽 금지.**

### 7-2. 토픽 → 비주얼 스타일 셀렉터
주제에 맞춰 `theme`을 자동 선택:
- 오디션 합격 공식·데이터·구조형 → **editorial-gold**(프리미엄 에디토리얼, 큰 인덱스·공식 카드).
- 동기부여·현실 직설·스토리형 → **stage-photo**(다크 시네마틱 스테이지 사진 + 레드 액센트).
- 하우투·단계·체크리스트형 → stage-photo 또는 editorial-gold + `checklist`/`body_html` 구조 카드 적극 사용.

### 7-3. 진실성 규칙 (가드레일 강화)
- **숫자·연구·랭킹·시장데이터를 날조하지 않는다.** 검증된 데이터가 있으면 사용, 없으면 "연구가 있는 척" 말고 경험·원리 기반 인사이트로 작성.
- stat 카드의 수치는 출처가 있을 때만. 없으면 정성적 표현으로 대체.

### 7-4. 언어 락
- 한 게시물의 가시 텍스트는 한 언어로 고정. KO판은 한국어만(영어 라벨 Slide/Hook/CTA 금지 → 도입/핵심/전환/실행/마무리), EN판은 영어만. 브랜드·고유명사만 예외.

### 7-5. 사일런트 품질 체크 (빌드 전 자동 검수)
배치 생성 직후 자동 점검(통과분만 승인 큐로):
- 가시 텍스트가 의도한 단일 언어인가
- 1장 훅이 충분히 날카로운가(통념 반박/냉정한 진실)
- 각 장이 다음 장을 필요하게 만드는가(open loop 유지)
- 한 슬라이드 한 아이디어 / 텍스트 벽 없음
- 근거 없는 수치·주장 없음(진실성 규칙)
- CTA가 리드마그넷 공식(가치+키워드)인가
- KO·EN 쌍 모두 생성됐는가 / dm_keyword 존재

### 7-6. 응답·출력 모드
이론·예고 설명 없이 결과물 바로 산출. 순서: 전체 콘셉트 → 슬라이드별 구성(화면 문구·레이아웃·그래픽 요소) → 배치 JSON(`build_cards.js` 입력). 정보 부족해도 질문 남발 말고 합리적 가정으로 1차 완성.
